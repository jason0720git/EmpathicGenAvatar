# 3DGS 음성 대화 스튜디오

접속: **http://127.0.0.1:5174/gaussian**

프로젝트 루트의 PowerShell에서 `./start-gaussian.ps1`을 실행하면 로컬 API,
웹 화면과 사진 생성 워커를 시작합니다. 이미 구성한 `audio2face-3d` 컨테이너가
정지 상태면 함께 시작합니다. Docker Desktop이 실행 중이어야 합니다.

## 바로 사용하기

1. 준비된 아바타를 선택하거나 **사진으로 아바타 만들기**에서 정면 사진을 올립니다.
   사진은 로컬 GPU에서 처리합니다. 생성은 한 번만 하며, 다음 접속에서도 재사용합니다.
2. **대화 시작**을 누릅니다. **눌러서 말하기**를 눌러 마이크 권한을 허용하고,
   말한 뒤 **말하기 완료 · 전송**을 누릅니다. 텍스트 입력으로도 음성 답변을 받을 수 있습니다.
3. **응답 중단**은 현재 음성과 모션을 함께 중단합니다. 새로 말하기를 시작해도
   이전 응답을 중단합니다. 최초 버전은 버튼으로 발화 구간을 정하는 방식입니다.
4. 오른쪽에서 표정·시선·머리를 시험할 수 있습니다. 수동 조절하면 그 값이 대화 중에도
   유지됩니다. **맥락에 따른 자동 공감 반응**을 다시 켜면 자동 계획으로 돌아갑니다.
5. 이상한 반응이 나오면 **피드백 남기기**에 상황을 적고 저장합니다.
   피드백은 해당 세션과 최근 턴에 연결됩니다. **로그 다운로드**로 같은 세션의 자료를 받습니다.

사용자 얼굴 분석은 선택 사항입니다. 기존 로컬 perception 서비스가 준비되어 있을 때만
사용하며 기본값은 꺼짐입니다. 음성·텍스트는 OpenAI Realtime API로 전달되고,
얼굴 생성과 Audio2Face 처리는 이 PC에서 실행됩니다.

## 무엇을 확인할 수 있나

- 실시간 렌더링 FPS, 실제 head bone 연결 여부, Gaussian 수
- 재생 대기 시간, 오디오 청크와 모션 프레임 수, 재생 지연·동기화 대기초과 횟수
- 행동 계획의 감정·의도·강도, 첫 음성·첫 모션까지 걸린 시간
- 입 벌림·미소·눈썹·눈·시선 등 현재 적용값과 모션 소스
- 단계별 이벤트, 오류, 세션 ID와 로그 다운로드

`data/gaussian/sessions/<세션 ID>/`에는 입력·출력 음성 PCM, 대화 전사,
Realtime 이벤트, A2F 원본·합성 계수, 행동 계획, 재생 측정값과 오류를 남깁니다.
PCM은 **24kHz / mono / signed 16-bit little endian**입니다. ZIP에 해석 정보도 포함됩니다.
API 키는 브라우저로 전달하지 않고 로그에서도 가립니다.

생성 기록은 `data/gaussian/jobs/`, 원본 사진·3DGS ZIP·모델/소스 해시는
`data/gaussian/avatars/`, 서비스 로그는 `data/gaussian/service-logs/`에 있습니다.
디버깅을 위해 로컬 음성과 전사가 계속 보관됩니다.

## 구현 범위

사진 → **LAM-20K의 리깅된 3DGS 얼굴** → 브라우저 WebGL 렌더링으로 이어집니다.
Realtime 출력 음성을 NVIDIA A2F에 보내 립싱크를 만들고, 별도 컨트롤러가
시선·헤드·비언어 표정을 합성합니다. 재생 음성의 시각에 맞춰 모션을 보간합니다.

현재 행동 컨트롤러는 SOBIA 구조를 참고한 **규칙 기반 초기 구현**입니다.
Realtime이 대화 맥락에 맞는 표현 의도를 계획하고, 컨트롤러가 채널 우선순위와
강도·범위를 적용합니다. 기존 연구의 인간 데이터 학습 모델을 이식한 상태는 아닙니다.
실제 공감 적절성과 표현 강도는 사용 피드백으로 별도로 검증해야 합니다.

현재 지원 범위는 얼굴·목/헤드입니다. 손·상반신 제스처는 포함하지 않습니다.
단일 사진의 가려진 부분·뒷머리·큰 회전에서 품질이 떨어질 수 있습니다.
중단한 assistant 답변은 일부를 들었더라도 다음 대화의 확정 히스토리에서 제외합니다.
이미 인식된 사용자 발화는 유지합니다.

LAM 가중치는 **CC-BY-NC-4.0**이며 FLAME 등 의존 자산에는 별도 조건이 있습니다.
현재 구성은 로컬 연구·검증용입니다. 배포·상용화 권한은 구성 요소별로 확인해야 합니다.

설계와 비교 근거: [시스템 설계](gaussian-avatar-system.md),
[논문·오픈소스 비교 및 생성 구조](gaussian-generation-research.md),
[A2F·행동 합성](gaussian-a2f.md), [생성 워커 설치](../workers/gaussian/README.md).
실제 검증 결과와 남은 평가 범위는 [검증 기록](gaussian-validation.md)에 정리했습니다.
얼굴 비율 및 눈 감김 수정 내용과 고정 프레임 검사 방법은 [리그 보정 기록](gaussian-rig-calibration.md)을 참고하세요.

## 개발 환경 복구

최초 의존성 설치는 프로젝트의 Python 가상환경에서 다음과 같이 수행합니다.

```powershell
.venv/Scripts/python.exe -m pip install -r apps/api/requirements-gaussian.txt
pnpm install
./start-gaussian.ps1
```

새 PC에서는 생성 워커 설치 문서의 모델 준비와 GPU 이미지 빌드를 먼저 수행합니다.
OpenAI 키는 기존 `.env`의 `OPENAI_API_KEY`를 사용합니다. 변경한 키나 서버 코드는
Gaussian API를 재시작해야 반영됩니다. API 8030, 웹 5174, 생성 8040, A2F 52000을 사용합니다.

화면이 준비되지 않으면 `data/gaussian/service-logs/api-error.log`와 생성 작업의
`worker.log`를 확인합니다. 서비스 준비 표시는 자격증명의 존재와 로컬 서비스 연결을
의미하며, API 권한·할당량은 실제 응답 요청 때 확인됩니다.
