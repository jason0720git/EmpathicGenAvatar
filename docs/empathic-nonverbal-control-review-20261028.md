# 공감 비언어행동 중심 재검토

> **2026-10-29 이력 추적 정정:** Ditto에 LivePortrait의 제어를 처음 연결해야 한다는 앞선 설명은 부정확했다. `a21b275`(2026-09-17, 표정 적용)에서 smile/brow/lip 편집을 Ditto의 `(1,63)` `delta_exp`로 이미 이식하고 v2→v3→v5 렌더 검증을 수행했다. 현재 `native8-speech-protected-v5-smile` 코드에도 적용되어 있다. 남은 제어 범위는 외부 입력에 따른 독립 눈동자 방향 등이며, 눈꺼풀 열림·깜빡임 보정까지 미구현인 것은 아니다. 근거: [v2](native8-expression-presets.md), [v3](native8-expression-v3.md), [v5](expression-v5-smile-and-concurrency.md), [rest-mouth](rest-mouth-calibration.md).

2026-10-28. 사용자가 명확히 한 우선순위: **얼굴 표정·눈의 움직임·머리 움직임을 원하는 시점과 강도로 조절하는 것이 핵심이며, 전신은 발화와 무관한 반복 모션이어도 된다.** 이 문서는 같은 날의 [전신 기술 조사](full-body-avatar-technology-review-20261028.md)의 적용 우선순위를 수정한다. 신규 모델 실행이나 제어 기능 구현은 수행하지 않았다.

## 1. 수정된 추천

**주력 구조는 명시적으로 제어 가능한 3D 얼굴/눈/머리 + 리그가 있는 몸의 반복 모션이다.** 3DGS만으로 만들 필요는 없다. 눈·눈꺼풀·구강은 제어 가능한 mesh/rig, 외형·머리카락은 Gaussian 등으로 구성하는 하이브리드도 유효한 설계안이다. 몸은 처음에 일반적인 skinned mesh로 충분하다. 순수 3DGS 여부보다 공감 행동을 재현하고 검증할 수 있는지가 중요하다.

단기에는 현재 **LAM 경로를 제어 인터페이스의 기준**으로 두고, **Ditto + LivePortrait의 눈/표정 제어 확장**을 영상 경로에서 비교한다. LAM을 그대로 최종 품질로 승인한다는 의미는 아니다. 기존 눈꺼풀 가림과 구강 문제가 해결되지 않으면 해당 자산은 탈락시킨다.

앞서 우선했던 LHM++, MegaAvatar, GestureLSM/EMAGE의 전신 생성은 후순위로 내린다. 전신의 음성 조건 생성은 이번 핵심 요건을 충족하는 데 필요하지 않다.

| 후보/경로 | 새 목표에 대한 위치 | 구체적인 이유 |
|---|---|---|
| 현재 LAM + 명시적 face/eye/head 제어 | **3D 제어 실험의 출발점** | ARKit eyeLook/eyeBlink, 표정, head 값을 이미 전달. 다만 입력 전달과 화면상의 올바른 동작은 별도 |
| Ditto + 기존 LivePortrait 유래 제어 | **기존 구현을 기준으로 검증·확장** | 표정·눈꺼풀·고개 제어는 이미 이식. 독립 눈동자 방향과 제어 간섭을 다음 대상으로 선정 |
| STEER | **가장 목적에 가까운 신규 연구 후보** | 경청/발화, 시선 맞춤/회피, 고개 리듬, 감정을 분리. 가중치 공개 및 렌더러 연결은 미해결 |
| ELITE | **얼굴 외형·표정 품질 비교 후보** | 짧은 단안 영상 기반 개인화, 시선/윙크의 개선을 저자가 제시. 정확한 임의 목표 시선 제어는 별도 검증 |
| FastAvatar / FlexAvatar / CAP4D | 얼굴 자산 품질 보조 후보 | 외형 재구성이 좋아져도 직접적인 눈 제어가 보장되지는 않음 |
| FlashHead Lite | 얼굴 영상 화질/지연 비교 후보 | 빠른 발화 영상과 독립적인 눈·표정의 수치 제어는 다른 능력 |
| LHM++ / ExAvatar / TaoAvatar | 몸 외형이 더 중요해질 때 | 현 단계에서 전신 개인화·학습·내보내기 비용을 우선할 이유가 줄어듦 |
| MegaAvatar / Wan-Animate / LongCat | 생성 영상 품질 비교, 후순위 | 생성 모델이 알아서 만드는 얼굴/몸 동작보다 요청한 비언어행동의 정확성이 우선 |

## 2. 현재 코드에서 발견한 빠른 개선 경로

현재 `workers/avatar/app/main.py`의 `build_ditto_ctrl_info`는 `gaze.x/y`를 작은 head yaw/pitch로 변환한다. 실제 눈동자를 움직이는 기능으로 해석하면 안 된다. 표정 프리셋도 pupil 관련 keypoint를 보호하도록 되어 있다. 반면 `vendor/LivePortrait/src/gradio_pipeline.py`에는 이미 다음 기능이 있다.

- `eyeball_direction_x/y`: 눈 주변 implicit keypoint를 변경하는 시선 편집.
- `input_eye_ratio`: 눈꺼풀 열림 retargeting.
- `input_head_pitch/yaw/roll_variation`: 머리 회전.
- smile, wink, eyebrow 등 표정 편집.

공식 현재 저장소에서도 동일 코드를 확인했다. 저장소 주소는 KwaiVGI에서 KlingAIResearch로 이동했다. [공식 retargeting 코드](https://github.com/KlingAIResearch/LivePortrait/blob/main/src/gradio_pipeline.py)

**수정된 제안:** 이미 구현된 Ditto 발화 모션 + LivePortrait 유래 표정 residual + blink-aware/speech-safe 보정을 출발점으로 한다. 두 독립 영상 생성기를 직렬 실행하는 방식이 아니라 Ditto 내부 motion/stitch 단계에서 합성하는 구조다. 기존 구현을 다시 만들지 않고, 눈동자 방향의 별도 입력과 head/gaze 분리부터 검증한다. Ditto 자체에도 `drive_eye`, blink schedule, `_fix_gaze`/`_eye_delta`가 있으므로 외부 LivePortrait 모델을 새로 실행해야 한다고 전제하지 않는다. 캐릭터별 좌표·중립값·stitch/자동 gaze 보정 순서와 간섭을 확인한다.

특히 LivePortrait의 눈 X/Y 값은 **보정된 3D gaze 각도 또는 공간상의 목표 좌표가 아니다**. Y 편집에는 눈꺼풀 보정도 포함된다. “명령 인터페이스가 있다”, “독립적이고 정확한 시선 제어가 된다”는 서로 다른 주장이다. 고정 머리 자세에서 좌우/상하 눈 이동, 눈 감김과 결합, 발화 중 립싱크 보존을 검사해야 한다.

3D 쪽 `apps/api/app/gaussian_behavior.py`는 이미 발화 입 모션과 얼굴·시선·고개 정책을 분리한다. 이 구조는 유지할 가치가 있다. 다만 `eyeLook*` 값이 전송됐다는 검사만으로는 부족하며 실제 홍채 방향, 눈꺼풀 폐쇄, 안구 돌출 여부가 합격해야 한다.

## 3. 새로 찾은 가장 가까운 연구: STEER

[STEER](https://kartik-teotia.github.io/STEER/)는 상대방의 음성/움직임과 아바타 음성으로 경청·발화 반응을 만들고, **시선 contact/avert, 고개 still/nod/shake/tilt, 감정 7종**을 따로 지정한다. 표정·턱·목·눈 회전·좌우 눈꺼풀을 포함하는 모션 표현을 사용한다. 단순 음성 기반 자동 표정보다 이 프로젝트의 공감 행동 제어 목적에 가깝다.

논문은 단일 RTX 5090에서 25fps와 약 290ms cue-to-render 지연을 보고한다. 그러나 이는 저자의 전체 시스템 수치다. 제어는 이산적인 행동 종류 중심이며 임의의 연속 시선 각도·각 AU의 강도·정확한 끄덕임 궤적을 모두 보장하는 인터페이스가 아니다. 좌우 눈 회전을 공통값으로 표현하는 제한도 있다. [논문 §5, Appendix F](https://arxiv.org/html/2607.23840v1)

**공개 상태를 확인하니 즉시 교체는 불가능했다.** 공식 inference 코드는 있지만 README의 checkpoint 링크는 TBA이고 Releases도 비어 있다. 공개 구성은 motion prior/autoencoder와 FLAME 시각화이며 논문의 photoreal Gaussian translator 전체가 포함된 완제품으로 보면 안 된다. 공개 예제 recipe는 10-step이고 논문의 실시간 distilled 구성과도 구분해야 한다. 코드/가중치 조건은 CC-BY-NC-4.0이다. [공식 코드](https://github.com/Kartik-Teotia/STEER), [Releases](https://github.com/Kartik-Teotia/STEER/releases)

따라서 **행동 모델의 연구 방향은 STEER, 현재 구현은 직접 제어 가능한 정책/리그**로 정한다. 가중치가 확보되면 같은 명령·같은 아바타를 구동해 기존 규칙/클립 기반 행동과 비교한다. 모델이 어떤 반응을 만들더라도 수동 제어와 중단 권한은 유지한다.

## 4. 얼굴 품질 후보의 순위도 바뀐다

**FastAvatar를 눈 제어의 해결책으로 추천하지 않는다.** 저자는 정밀 gaze를 정확히 포착하지 못하고 평균 방향으로 수렴하는 한계를 명시한다. 외형 재구성 비교군으로는 유용하지만 이번 핵심 평가에서 이 항목을 반드시 분리한다. [FastAvatar limitations](https://arxiv.org/html/2508.19754v2)

**ELITE를 추가 비교군으로 올린다.** CVPR 2026의 단안 영상 기반 Gaussian head 개인화 방식으로, 프로젝트에서 시선 변화·한쪽 눈 윙크 등의 표정 일반화 개선을 보여준다. 공식 코드에는 전처리→개인화→모션 구동 절차와 checkpoint 다운로드 안내가 있다. 다만 참조 환경은 A6000 48GB이며 5090 32GB 적합성과 직접 수치 제어의 정확성은 확인되지 않았다. 현재 단일 생성 사진만 있는 캐릭터에 동일한 이득이 생긴다고 볼 수도 없다. [프로젝트](https://youwangk.github.io/elite), [공식 코드](https://github.com/kaist-ami/ELITE)

**정밀 시선이 계속 실패하면 표현 구조를 바꿔야 한다.** 얼굴 Gaussian 전체를 움직이는 것만으로 홍채·안구·눈꺼풀이 일관되게 분리되지 않을 수 있다. 독립 안구 회전과 눈꺼풀/주변 피부 변형을 모델링하는 방향은 [Roll Your Eyes](https://arxiv.org/abs/2508.06136)와 [Relightable Gaussian Codec Avatars](https://shunsukesaito.github.io/rgca/)에서도 다룬다. 이 연구들을 현재 한 장 생성 경로의 즉시 대체품으로 제안하는 것은 아니며, 눈 geometry/제어 구조의 근거로 사용한다.

우리의 구현 선택은 **눈·눈꺼풀·턱의 명시적 리그와 깊이/가림을 갖춘 mesh 또는 hybrid head**가 될 수 있다. [MeGA](https://github.com/conallwang/MeGA)는 얼굴 mesh와 머리카락 Gaussian의 결합 사례지만, 이 역시 개인화 학습이 필요한 구조 참고이며 단순 LAM 플러그인이나 완성된 gaze 솔루션은 아니다.

## 5. 전신은 이렇게 단순화한다

첫 버전은 캐릭터에 맞춘 skinned mesh body와 고정 root를 사용한다. 제안하는 클립은 편안한 대기/호흡, 경청 자세, 약한 체중 이동, 작은 손 정리, 차분한 말하기 자세 정도다. 모두 새 모션 모델 없이 사전 제작한 반복 애니메이션으로 구현 가능한 설계다.

- 클립 사이를 crossfade하고 반복 시작점을 분산한다. 반복을 숨기려고 큰 움직임을 계속 추가하지 않는다.
- 몸 클립의 neck/head 트랙은 제거하거나 제한해 공감 제어기가 고개를 소유하게 한다.
- 어깨·척추의 작은 움직임은 허용하되 머리는 부모 좌표계에서 보정한다. 얼굴과 몸의 목 연결·피부색·조명·크기를 맞춘다.
- 첫 버전은 손이 얼굴 앞을 지나가는 클립을 쓰지 않아 합성 범위를 줄인다. 이후 가림을 추가할 때는 동일 depth/camera에서 렌더한다.
- 몸의 강도는 얼굴 행동을 방해하지 않을 정도로 둔다. 공감 표현 효과를 비교할 때는 동일한 body clip/seed를 사용한다.

영상 경로에서 몸 루프에 얼굴을 합성하는 것도 가능하지만 고정 카메라·작은 어깨 움직임·제한된 머리 회전부터 검증해야 한다. 자유로운 시점과 큰 움직임이 필요하면 공유 3D 리그가 있는 쪽이 연결을 관리하기 쉽다는 설계 판단이다.

## 6. 구현의 중심은 감정 라벨보다 행동 시간표

`happy/sad` 선택만으로 공감 행동을 정의하지 않는다. 상위 정책은 주의 유지, 이해 표시, 조심스러운 반응, 발화 준비, 경청 복귀 같은 의도를 선택한다. 하위 제어는 다음 값을 시간 궤적으로 만든다.

| 제어 | 필요한 값 |
|---|---|
| 표정 | 눈썹·눈꺼풀·입꼬리 등 캐릭터별 유효 강도, 시작/유지/해제 시간 |
| 시선 | 목표와 좌표계, gaze hold, 회피 후 복귀 시각. 눈꺼풀 열림과 별도 취급 |
| 고개 | yaw/pitch/roll 또는 quaternion, 끄덕임 횟수·진폭·속도, 기울임의 유지/복귀 |
| 발화 | 현재 A2F/음성 기반 입 동작, 감정 합성에서 보존할 발음 영역 |
| 몸 | 클립 ID, phase, 강도, 전환 시간 |

예를 들어 “상대를 보면서 약한 걱정 표정을 유지하고, 특정 시점에 한 번 끄덕인 뒤 경청 자세로 돌아오기”를 같은 입력에서 재현할 수 있어야 한다. 이는 설계 예시이며 모든 사용자·문화·상황에 보편적으로 공감적이라는 주장이 아니다. 상대의 부정적 감정을 그대로 과장해서 따라 하는 것을 기본 정책으로 두지 않는다.

**추천 순서:** 얼굴·눈·머리의 개별 제어 검증 → 침묵 중 경청 행동과 복합 제어 → 작은 body loop 연결 → 필요할 때 더 자연스러운 행동 prior(STEER 등) 비교.

## 7. 교체 여부를 결정할 테스트

1. 머리 고정 상태에서 눈만 좌우/상하 이동하는가? 눈 이동이 고개 이동으로 대체되지 않는가?
2. 눈 방향을 유지하면서 깜빡이기, 표정·끄덕임을 동시에 적용해도 홍채/눈꺼풀/안구가 깨지지 않는가?
3. 표정의 강도와 onset/hold/release가 반복 실행에서 재현되는가? 원하는 시점에 개입·취소할 수 있는가?
4. 말하지 않는 경청 상태에서도 표정·시선·고개를 자유롭게 제어할 수 있는가?
5. 발화 중 표정을 바꿔도 입술 폐쇄와 립싱크를 보존하는가?
6. 같은 body loop에서 얼굴·눈·고개만 바꾼 비교를 통해 사용자가 의도한 반응을 구별하는가?

제어 오차·다른 부위로의 간섭·시각적 품질·공감으로 인지되는 정도를 따로 평가한다. 좋은 화질, 높은 FPS, 정확한 API 전달만으로 이 네 조건을 대체할 수 없다.
