# 3DGS 대화 아바타 개선안 검토

검토일: 2026-09-29. 범위: 현재 코드·자산 이력 확인, 논문 원문·저자 저장소·공개 코드 확인. 신규 모델 설치·추론 비교는 수행하지 않았다. 아래 추천은 실측 우승 모델 선정이 아니라 다음 실험의 우선순위와 설계안이다.

## 결론

품질 우선 목표는 **개인화된 변형과 외형을 학습한 3DGS + 눈/구강 구조 제약 + 실제 움직임 기반 대화 제어**다. 생성 모델 한 개 교체로 이 세 문제를 동시에 해결할 수 없다.

현재처럼 원본이 한 장인 가상 인물은 **CAP4D를 품질 우선 생성 실험의 1순위**로 선정한다. 표현·시점 조건부 생성으로 관측을 보완하고 사람별 Gaussian 아바타를 피팅하는 경로다. 실제 인물을 촬영할 수 있으면 **표정이 충분한 영상 → FastAvatar 및 FlashAvatar 비교**, 충분한 다중 시점 촬영이 가능하면 **GaussianAvatars 개인화 학습**을 우선한다. 눈/입 실패가 남는 경우에는 메쉬와 Gaussian을 결합하는 구조를 별도 개발해야 한다. 여기서 하이브리드는 화면 위에 이미지나 치아를 얹는 방식이 아니라 일관된 3D 깊이·가림·관절 변형을 가진 구조다.

## 3. 제안하는 생성·제어 구조

### 생성

1. 변경 없는 LAM 원본/공식 Python 구동을 기준으로 저장한다. 현재 파생 자산과 같은 포즈·카메라로 비교해 보정/내보내기/렌더러 문제를 모델 한계와 분리한다.
2. 가상 인물은 CAP4D로 원본 사진의 identity를 고정하면서 시점·표정을 조건으로 관측을 보완한다. 독립 이미지 프롬프트 여러 개로 치열·턱·조명을 각각 만드는 방식은 피한다.
3. 생성된 관측은 동일 치열, 중립 비율, 좌우 눈·입술 위치, 시간/시점 일관성으로 검수한다. 깨진 생성 결과로 학습하면 오류가 아바타에 고정된다.
4. 정합된 개인별 아바타에 중립·깜빡임·입 벌림·미소·발음 조합의 보정 변형을 학습/피팅한다.
5. 가림 실패가 남으면 윗니/아랫니, 구강 내부, 눈알/눈꺼풀을 일관된 3D 구조로 분리한다. 윗니는 두개골, 아랫니는 턱에 결합하고 눈꺼풀 폐쇄와 안구 가림을 공동 처리한다. 독립 혀가 요구되면 실제 tongue rig와 제어 소스가 추가로 필요하다. 기존 색 마스크 재도입으로 대체하지 않는다.

실촬영이 가능할 경우 초기 실험 입력으로 1~3분의 고정 조명 영상과 중립/좌우 회전/감은 눈/열린 입/다양한 발음을 제안한다. 이 길이는 논문의 필수값이 아니라 파일럿 촬영안이며, 자료 충분성은 표정·시점 커버리지로 판단한다. 다중 시점이 추가될수록 가림 부위 관측을 늘릴 수 있다.

### 모션

Realtime 응답 음성 → A2F 립싱크 + 실제 인간 모션 클립/저지연 모션 모델 → SOBIA 맥락·공감 정책 → 부위별 우선순위 합성 → 캐릭터별 정상 변형 범위 → 렌더러.

- 자연스러움은 임의 흔들림의 크기보다 눈·볼·입·고개의 동시성과 문장 강세/쉼에 대한 관계가 중요하다. v8의 절차적 noise는 저강도 보조로 남기고, 주 움직임은 실제 촬영 모션의 조건부 선택/혼합으로 바꾼다.
- SOBIA는 반응 종류·시점·강도와 시선 목적을 결정한다. LLM이 매 프레임 독립 blendshape 값을 직접 생성하게 하지 않는다.
- 립싱크·감정·눈깜빡임이 같은 부위에서 경쟁하지 않게 한다. A2F와 다른 모델의 전체 입 모션을 단순 합산하지 않는다. FLAME 계수의 인덱스가 곧 해부학적 부위인 것도 아니므로 영역 마스크를 적용한 정점/리그 공간 피팅이 필요하다.
- ARKit→FLAME 근사 변환은 별도 비교 대상이다. FLAME-native driver와 같은 아바타를 구동해 변환 손실을 분리한다.
- 100%는 '모든 weight=1'이 아니라 그 인물의 검증된 최대 감정 표현으로 정의한다. 개별 coefficient가 0~1 범위여도 조합이 유효하다는 뜻은 아니다.

### ARTalk의 위치

[ARTalk](https://github.com/xg-chu/ARTalk)은 음성에서 FLAME 표현·머리 모션을 생성하므로 WAV 비교/모션 다양성 기준으로 적합하다. 다만 공개 streaming 코드는 4초/100프레임 청크를 요구하며, 동일 출력 smooth 경로는 160ms를 더한다. 빠른 추론 FPS를 낮은 대화 응답 지연과 혼동하면 안 된다. 따라서 **ARTalk 전체를 Realtime API 뒤에 즉시 교체 연결하는 것을 기본안으로 선정하지 않는다**. 우선 WAV 품질 비교에 사용하고, 실제 대화는 A2F+인간 모션 라이브러리로 지연을 억제한다. [저자 realtime notes](https://github.com/xg-chu/ARTalk/blob/main/docs/realtime.md)

## 4. 검증 순서와 합격 기준

| 단계 | 고정할 조건 | 무엇을 판단하나 |
|---|---|---|
| A. 생성/렌더러 분리 | 동일 얼굴·카메라·기록된 driver, dynamics off | upstream LAM vs 파생 자산 vs web export |
| B. 생성 후보 비교 | 동일 입력·동일 native FLAME driver | LAM/GAGAvatar/CAP4D 및 촬영 가능한 경우 FastAvatar/FlashAvatar |
| C. 모션 비교 | 가장 안정적인 동일 아바타 | A2F 단독, v8, ARTalk, A2F+실제 인간 모션 |
| D. 정책 합성 | 동일 대화/WAV·다양한 감정 | 부정 감정의 미소 혼입, 시선·끄덕임 시점, 발음 보존 |

초기 수용 조건(프로젝트 제안값):
- 정면·좌우30°에서 연속 깜빡임 시 안구 노출/눈꺼풀 찢김이 눈에 띄지 않을 것.
- 점진적 입 벌림과 한국어·영어 발화에서 치열 부유·경계 중첩·비정상적인 구강 색 점프가 없을 것.
- 단일 채널뿐 아니라 미소+입 벌림, 깜빡임+시선, 분노+발음 같은 조합을 통과할 것.
- 정체성 유지와 자연스러움을 블라인드 비교로 함께 평가할 것. PSNR/landmark/GPU coefficient 통과만으로 품질 합격 처리하지 않을 것.
- 최종 음성/렌더 동기와 p95 프레임 시간 측정. 30fps 목표라면 프레임 예산33.3ms, 새 모션층 추가 지연 목표200ms 이내로 설정하고 미달을 기록한다. 이는 실측 결과가 아닌 목표다.
- 단일 동아시아/유럽계 캐릭터만으로 인종 효과를 주장하지 않는다. 여러 정체성, 눈 형태, 조명, 사진 조건을 포함한다.

로그: 원시 모션, 정책 출력, 제약 전/후 모션, 제한 발동 채널/이유, 영역별 변형량, 오디오 PTS, 렌더 PTS, VRAM, 지연, 모델/자산/카메라 버전, 실패 프레임을 함께 저장한다.

## 5. 적용 현실성

현재 장비 확인: RTX 5090 약32GB VRAM, 시스템 RAM 약125.6GiB. 신규 후보의 실측 VRAM/처리시간은 미확인이다. 생성 작업과 A2F/실시간 렌더러 동시 사용은 피하고, 우선 512 해상도·작은 batch로 비교한다. 5090에 맞는 CUDA/PyTorch/커스텀 rasterizer 빌드는 별도 검증한다.

연구와 제품화 조건을 구분한다. CAP4D는 CC-BY-NC-4.0, GaussianAvatars는 CC-BY-NC-SA-4.0로 공개된다. FastAvatar 코드/모델 카드는 Apache-2.0이지만 FLAME 등 종속 자산의 조건은 별도다. OMG-Avatar는 저장소의 사용 제한 때문에 공감 대화 제품의 기본 후보로 바로 선정할 수 없다. 코드 공개와 상업 이용 가능은 같은 의미가 아니다.

가장 먼저 실행할 실험은 **무수정 LAM 기준 복구 + 현재 원본 두 장의 CAP4D 생성 비교 + 동일 driver 평가**다. 모양이 안정된 뒤 실제 인간 모션 기반 제어를 올린다. 이 순서를 지키면 입/눈 생성 오류를 dynamics 증폭으로 더 크게 드러내는 반복을 피할 수 있다.
